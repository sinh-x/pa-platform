# Rogue-One configuration retention

PAP-349 separates configurable instructions from native admission. PAPC-110 owns
Rogue-One configuration/default-model adoption. A runtime source pass does not
establish that the operator has adopted that configuration or installed this PAP.

## Supported consumer

Foreground PPA CLI selects a ticket-optional, profile-free interactive mode.
The exact native Rogue-One identity retains its admission exception. Configuration
cannot select protected capabilities, acquire builder custody or launch helpers.
OPA, background, Agent API deployment and WebSocket execution reject configured
Rogue-One until their consumers support this retention contract. Operator API
authentication still precedes its unsupported-route rejection.

## Capture and bounds

The native launcher captures the working bytes it actually consumes, not Git HEAD.
It records selected team/mode configuration, effective runtime pair and source,
original objective/overrides, and the selected instruction/resource closure.
Capture rereads observed file identities and bytes, including absent optional
references, before using the snapshot. Source changes or interruptions reject.

Each resource is a regular, singly linked UTF-8 file without symlink aliases,
subject to the existing sensitive-content checks. The finite inventory permits
256 files/absent references, 1 MiB per file and 16 MiB of original content. Its
canonical JSON envelope permits 24 MiB including JSON escaping and metadata.
Exceeding any bound rejects; it does not truncate. Review JSON consumers retain
their existing 1 MiB default: only this native archive owner selects the larger
bounded parser envelope.

The allowed config-owned namespaces are `teams`, `skills`, `docs`, `primers`,
`policies`, `contracts`, `scripts` and `workflows`. Retained workflow/schema text
is inert reference content, not a workflow selection, approval or native grant.
Absolute/foreign/traversing resource targets cannot extend this inventory.

## Instructions and reference-only material

Selected objectives, guides, repository guides, agent instructions and skills are
instruction roots. Existing agent skill names resolve to
`skills/global/<name>/SKILL.md`; an explicit Markdown resource remains a path.
Selected-once guides and skills are composed without reactivating unselected agents.

Markdown links, including reference-style links, retain their config-owned target
bytes and transitive literal links. JSON `$ref` dependencies and passive HTML
links are also retained. Bare config-owned locators in selected instructions,
including inline helper commands, select supporting resources when present.
Illustrative absent bare paths remain recorded absences, never live fallbacks.

A linked manual/example retains its full bytes and links but does not activate
that other role's bare shell examples as this mode's instructions. For example,
a link to a Builder example does not select its illustrative source-test command
as a Rogue-One execution obligation. An explicit selected instruction/helper or
file link still retains its actual supporting dependency graph. Reading reference
material or retaining code grants no permission to run it.

## Static JavaScript helpers

The existing pinned TypeScript parser is a runtime dependency, loaded lazily only
when a selected JavaScript helper requires discovery. No config script is imported
or evaluated during capture. This avoids a second ad-hoc JavaScript tokenizer;
it adds the compiler's production footprint, not a new evaluator or native grant.

Supported JavaScript graphs include literal relative named/side-effect imports,
direct declaration exports, config-root literal resource data, and file URLs
resolved from unambiguous local/imported `const` strings and flat primitive arrays,
literal indexes, concatenation and template expressions. Shadowed bindings,
mutated/escaped arrays reject rather than guessing. Local namespace/default
imports, re-exports, dynamic imports and CommonJS `require` are unsupported;
these can expose shared selectors outside the named-binding graph. Computed
property names other than numeric literal reads or finite immutable for-of
dictionary keys, and opaque process/reflection loaders, are also unsupported.
File URLs resolve relative to their module, independently of config-root data
locators. Filesystem string paths depend on runtime CWD and are unsupported;
only verified file URLs or explicit caller-input paths are accepted. Numeric addition retains JavaScript numeric semantics;
it is not treated as string concatenation. Selector evaluation is limited to
8,192 steps per script, depth 32 and 4,096 characters per constructed string;
concatenation is checked before allocating its result. The AST walk permits
200,000 nodes per script. External npm/absolute module resolution is unavailable.
Built-in Node modules remain current runtime dependencies, not saved credentials
or frozen native policy. Delegating loaders/process modules and opaque CommonJS
filesystem loading are unsupported.

ES-module filesystem readers may use explicit caller input (`process.argv`) or
finite captured file URLs. Directory discovery, unresolved file/module/URL
selectors, rebinding filesystem readers, `eval`, function construction and unknown
supporting resource types reject. This is a bounded dependency grammar, not a
JavaScript sandbox or proof about arbitrary code. The real PAPC report checker,
its imported contract module and its template resources have a paired source test
that executes the retained checker against a synthetic report after deleting the
fixture's entire original configuration directory. It does not delete live PAPC.

## Persistence and continuation

The original immutable native start binds the versioned snapshot's digest to its
deployment/runtime/repository/mode/pair context. A manifest/hash or filesystem mode
alone does not establish origin or same-UID confinement. The recorded native
runtime session and protected ancestry are checked separately. Native lineage
inspection precedes Rogue-One configuration/repository selection and unsupported
route rejection, including the PPA preflight hook. A caller cannot hide a protected
or missing original lineage behind a different team selector or config error.

Projection and archive writes are absent-only and read back before use. An existing
matching result can be reconciled after a lost acknowledgement; a partial,
conflicting or writable replacement is preserved and rejected, never overwritten.
A continued deployment gets a distinct native binding without rewriting its source.
The launcher rechecks current safety, session evidence and captured resources at
its actual before-runtime-start boundary.

Resume consumes only the original verified configuration/resources/pair/overrides.
Changing or deleting live PAPC does not refresh those instructions. Conflicting
requests, unknown/tampered/incomplete snapshots, crossed roots or missing legacy
evidence block continuation without migration or a current-config fallback.
Original native Rogue-One lineage cannot be resumed through another team's
same-named mode; classification occurs before adapter configuration selection.
Filename, original-path and content privacy policies are reapplied at capture,
resume and immediate admission, including newly sensitive originally absent paths.
Missing or invalid PA-owned security defaults preserve their fixed package-policy
guidance; they are not misreported as corrupt original snapshots or missing config
resources, and retained instructions never replace required security defaults.
Current credentials, host/tool policy, native custody and protected ancestry are
not frozen by retained instructions. Preserve uncertain original operations and
route reconciliation to their native owner; do not delete evidence or blindly
create a replacement run.

## Evidence limits

Hermetic source tests cover retention, tamper/identity/closure faults and actual
launcher/adapter seams. The separately selected paired fixture checks current
PAPC bytes without editing that repository. Source tests and static report checks
are not independent Review, installation, foreground operator observation or
human UAT. Those remain separately owned qualifications for the exact candidate.
