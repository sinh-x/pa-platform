## High priority — blocking

### 1. Production Analyst starts never receive the process evidence required for authentication

**Locations:** `packages/pi-pa/src/document-session.ts:61-65,83`; dependency `packages/pi-pa/src/process-identity.ts:73-79`; production call `packages/pi-pa/src/adapter.ts:1370`.

It does nothing for `analyst/analyze`. Consequently a genuine public launch lacks `pi-process-identity.json`; document authentication and selected tool registration/direct invocation fail. This is not merely an installed-verification limitation.

**Counterexample:** calling the actual production writer with the current disposable PID produced `analyst false`, then `requirements true` for file existence. New session/status tests instead call `recordPiProcessIdentity` manually (`analyst-identity-session.test.ts:38`, `analyst-identity-ticket.test.ts:27`), concealing the integration gap.

**Minimal fix/test:** add the qualified public route to the existing production writer, without loosening fingerprint/lineage checks. Run the real adapter admission path against a disposable child/PTY seam, then authenticate/register/invoke a selected tool without manually planting its anchor. Include an omitted-policy negative.

### 2. The claimed pre-spawn check does not protect the actual adapter start or its live skill inputs

**Locations:** `packages/pi-pa/src/deploy.ts:1549,1559-1565,1580`; `packages/pi-pa/src/adapter.ts:277,301`.

Freshness is checked before entering `adapter.spawn`. The real adapter then awaits preflight and supplies original mutable configuration paths through `--skill`. Public policy launches receive no `beforeRuntimeStart` callback: that callback is currently reserved for auto-launch/retained resume. Capturing safe primer text therefore does not prevent a different skill body from entering the child under the saved V2 binding.

**Counterexample:** a disposable committed selection used the real `PiAdapter` with an inert `runCommand` sink. A queued mutation during the adapter's preflight await changed its selected skill. Output was `HAS_START_RECHECK false`, `NATIVE_COMMAND_SKILL true READS_DRIFT true`, and `LAUNCH success native invocations 1`. No actual Pi process was spawned. The existing launch test uses a replacement adapter and mutates much earlier in `installHooks`, so it cannot prove this boundary.

**Minimal fix/test:** compose the selection reread into the existing native child-start gate and make every policy-launch caller honor it. Feed native skill loading from the authenticated captured closure, not the mutable selected checkout. Test drift during adapter awaits/child admission and inspect actual command skill paths/bytes; require no release of a child with mismatched resources. Preserve existing auto/resume gate ownership.

### 4. Canonical issuance during asynchronous view loading can still become a false foreground failure

**Location:** `packages/pa-core/src/documents/handoff-review.ts:147-156,158-181`.

The shared-journal observer and reconciliation handling start only after `await local.view`. If another medium issues the original decision while that view is pending, a later view rejection escapes without checking the saved decision. A successful view also proceeds to capture without checking whether issuance occurred during the await. The held-dialog tests cover neither window.

**Counterexample:** a disposable real-journal service probe issued the original approval at the delayed view boundary, then surfaced a view `DOCUMENT_SOURCE` failure. The foreground returned `FOREGROUND_ERROR DOCUMENT_SOURCE` while the journal retained `CANONICAL approved` and `['requested', 'issued']`. The controlled view boundary is a deterministic source race probe, not an installed reproduction. Its initial setup attempt omitted required FULL durability and was corrected; that setup rejection is not a product failure.

**Minimal fix/test:** put asynchronous view acquisition inside the same original-request reconciliation envelope; check for saved issuance/staleness after the await and on its error path, before opening capture. Preserve exact historical replay, original coordinates and origin validation. Test external approval/nonapproval/stale settlement during delayed/rejected view loading, plus revoke settlement and disconnect races, with zero extra capture or synthetic Cancel.

## Medium priority — blocking boundary defect

### 5. A review connection can pipeline unrelated Hono work despite the stated isolation fence

**Location:** `packages/pa-core/src/agent-api/routes/local-review.ts:124-130`; related upgrade handling at line 198.

The non-review fallback calls the ordinary listener before checking the connection's request count or whether review claimed it. Thus a review request followed by an unrelated request on the same socket dispatches unrelated work, even when the review itself is rejected. `Connection: close` on the first response does not undo a handler already invoked.

**Counterexample:** one raw socket sent an invalid-schema POST to the exact review endpoint followed immediately by `GET /unrelated-effectful-route`. The first reply was HTTP 400, but a harmless recording listener observed `GENERAL_HANDLER_RAN /unrelated-effectful-route` and `PIPELINED_GENERAL_COUNT 1`. No document owner or effect was invoked by this probe.

**Minimal fix/test:** mark review-owned connections before asynchronous work and reject every subsequent request/upgrade before the general-listener fallback. Do not disable ordinary non-review keep-alive globally. Test accepted/rejected/slow review followed by unrelated state-changing routes and upgrades, asserting zero fallback side effects; retain independent health/CORS/WebSocket positives.
